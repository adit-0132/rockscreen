# CLAUDE.md: Rockscreen (formerly verseLock)

Android app that shows time-synced lyrics over the lock screen for whatever a media-session player is playing.
Package `io.github.adit0132.rockscreen` (permanent), repo `adit-0132/rockscreen`, GPL-3.0. The local folder is
`~/Projects/verseLock` on purpose: never rename it.

## Build and test
- JDK 17 or 21. JDK 25 (the system Java and Android Studio's JBR here) is too new for Gradle 8.11.
- `./gradlew assembleDebug testDebugUnitTest lintDebug`. compile/target SDK 36, minSdk 27, AGP 8.9.3, R8 on for release.
- Until the planned history purge, `app/build/` is tracked in git: build in a copy
  (`rsync -a --exclude app/build --exclude .gradle ./ /tmp/rs-build/`) so build outputs don't show up as changes.
- Release signing comes from a git-ignored `keystore.properties`; without it the release APK is unsigned.

## How it works
- `service/MediaListenerService` (NotificationListenerService, bound by the system) follows the active media session
  (prefers the one that's playing), turns metadata into `TrackInfo` and playback state into a position, and feeds
  `service/PlaybackHub` (process singleton of StateFlows). It also listens for SCREEN_ON/OFF/USER_PRESENT.
- `PlaybackHub.onTrackChanged` looks lyrics up through `data/repository/LyricsRepository` (Room cache, 30-day TTL,
  misses cached too) and `data/network/LrcLibApi` (`/api/get`, title + artist, app User-Agent, timeouts).
- `service/LockScreenLauncher.maybeShow` opens `ui/LockScreenActivity` over the keyguard only while playing, with lyrics
  not NotFound, and only when asleep or locked: a full-screen-intent notification when the screen turns on (posting one
  while the screen is off makes SystemUI wake the display), or a direct start if "Display over other apps" was granted.
- `LockScreenActivity`: showWhenLocked, keeps the screen on only while playing with lyrics shown, closes on unlock
  (exported USER_PRESENT receiver, since SystemUI sends it, plus a 500 ms keyguard poll), 30 s grace after pause.
- No foreground service, nothing starts at boot. WorkManager runs a weekly cache clean-up.

## Decided behaviour (don't undo without asking)
Decisions are in `launch/launch-strategy.md` §9. Highlights: closes on unlock; needs a lock screen; screen stays on while
lyrics stream and the power button sleeps it (D12); Spotify's " • Recommended for you" artist tag is stripped (D10);
media flagged as ads is skipped (D11); the app UI is not restyled to the launch brand.

## Known issues (accepted for v1)
H4 (failed lookups cached 30 days), H5 (stale fetch can overwrite a fast skip), M1–M3 (artwork edge cases, bitmap-path
metadata storms), M5 (LRC parser gaps). Details: `launch/REDTEAM-REPORT.md`; user-facing list: README.

## Where things are
- `launch/` (untracked working material): strategy and decisions, red-team report with device verification, research,
  brand (`brand/brand.md`; icons are generated by `brand/build_icons.py`, which also writes the launcher/notification
  drawables), demo content and the `demo.player` MediaSession harness, `qa/lockscreen_qa.sh` behaviour matrix.
- On-device notes: the user's test phone is a vivo (Android 15) that hides app logs (`log.tag=M`); debug with a file
  log via `run-as`. Turn off "stay awake while charging" on the emulator before screen-timeout tests.
